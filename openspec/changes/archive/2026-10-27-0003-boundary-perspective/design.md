# Design

## Context

见 `proposal.md`。参考项目 `CardScanner` 只使用固定取景框裁剪，不含矩形检测与透视变换，因此本模块需要新建，不能照搬。所有几何计算必须可解释，便于在失败案例上分析。

## Goals / Non-Goals

**Goals:**

- 检测结果与人工调整使用同一套角点模型，避免"自动一套、手动一套"。
- 校正后的图像可直接用于 OCR，且方向可读。
- 检测失败不阻断流程，但必须显式提示。

**Non-Goals:**

- 不追求与 CamCard 逐像素一致。
- 不实现曲面展平（书籍扫描）。
- 不做实时视频流检测（仅对静态帧）。

## Decisions

1. **角点统一使用图像坐标（左上原点、像素）**
   - Vision 输出左下原点，检测器内一次性转换；UI 只处理归一化坐标再乘以图像尺寸。
   - 备选：全链路使用归一化坐标（被否：裁剪与透视滤镜需要像素坐标，转换点更多）。

2. **用 `VNDetectRectanglesRequest` 而非文档分割**
   - 理由：名片为规则四边形，矩形检测参数可直接约束长宽比与角点容差；文档分割面向曲面纸张。
   - 备选：`VNDetectDocumentSegmentationRequest`（被否：对名片这类小目标不稳定，且返回的是掩码）。

3. **检测失败回退整图而非报错**
   - 理由：用户仍可手动四角调整并继续，符合 `card-detection` 的"不可用"场景。
   - 备选：强制重拍（被否：无文字名片的可恢复性差）。

4. **旋转在最终输出时用 EXIF orientation 应用**
   - 理由：避免在预览层做坐标变换导致角点错位；预览标注"输出将旋转 N°"。
   - 备选：旋转预览图并同步旋转角点（被否：实现复杂度高，收益低）。

## Risks / Trade-offs

- [复杂背景下矩形检测可能命中桌面或 Logo 边缘] → 置信度阈值 + 人工确认；失败案例计入检测报告。
- [预览未旋转，最终输出旋转，可能造成用户预期偏差] → 界面显示旋转角度提示；后续可用 UI 测试固化。
- [检测在主线程外执行，`UIImage` 跨 actor 传递存在并发告警] → 首次 CI 构建时确认；必要时改为传 `Data` + `CGImage`。

## Migration Plan

无数据迁移。`CardQuad` 为新增值类型，不影响既有持久化 schema。
