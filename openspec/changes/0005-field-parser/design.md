# Design

## Context

见 `proposal.md`。这是整个项目风险最高的一环：分类错误可以靠人工修正，但"编造不存在的字段"会直接违反验收要求。实现必须在"尽量识别"与"绝不猜测"之间偏向后者。

## Goals / Non-Goals

**Goals:**

- 规则可解释：每个字段都有来源行与命中规则。
- 多值字段（手机/办公/传真/邮箱）顺序稳定、去重可靠。
- 缺失字段不允许出现空字符串或推断值。

**Non-Goals:**

- 不实现机器学习分类器。
- 不做跨名片去重或身份合并。
- 不解析二维码/头像。

## Decisions

1. **标签优先、模式次之、启发式最后**
   - 顺序：`标签 → 邮箱/网址/电话正则 → 公司/职位关键词 → 姓名形状 → 地址关键词 → 待定区`。
   - 理由：标签是名片上最强的人工信号；启发式误判成本最高。
   - 备选：纯正则（被否：无法处理中英混排与无标签名片）。

2. **无法确定时进入 `unresolvedLines`，不写字段**
   - 理由：符合"AI 不允许补全"的硬约束；用户可在校正页查看。
   - 备选：取最高概率候选（被否：会产生虚构字段，直接违反验收）。

3. **多值字段使用数组，保存时按行拆分**
   - 理由：名片常见多个号码；数组比拼接字符串更利于导出与编辑。
   - 备选：单字符串 + 分隔符（被否：无法区分类型，vCard 映射困难）。

4. **诊断信息与结果同构**
   - 理由：字段级准确率评估需要知道"为什么这样分类"。
   - 备选：只输出字段（被否：错误无法归因）。

5. **中文姓名与公司用字符集与关键词区分，中英混排单行按 token 拆分**
   - 理由：`朱宏明 Professor Tongji University` 这类单行名片无法靠整行规则处理。
   - 备选：依赖 OCR 分行（被否：OCR 合并行时失效）。

## Risks / Trade-offs

- [规则在未知名片集上召回率有限] → 接受；用 Ground Truth 量化并把失败样本写入报告。
- [公司/职位关键词可能误伤姓名（如 "Lee Consulting"）] → 公司判定先于姓名；仍无法区分时进入待定区。
- [中文姓名长度假设 2–4 字] → 复姓/少数民族姓名可能漏判；记录为已知限制。
- [多行地址拼接使用换行] → vCard 导出需转义；由 `VCardBuilder` 处理。

## Migration Plan

无数据迁移。解析结果只在校正页生效，保存结构由 `0006` 决定。

## Open Questions

- 是否需要字段级置信度（而不仅是诊断）？当前使用 OCR 置信度 + 规则命中，暂不引入额外评分。
