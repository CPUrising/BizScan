# Design

## Context

见 `proposal.md`。参考项目 `CardScanner` 使用 `VNRecognizeTextRequest` 但只设 `.accurate` 且关闭语言纠正，默认语言无法覆盖中文；本项目需要中英混排，且必须保留原始文本供评估。

## Goals / Non-Goals

**Goals:**

- 单次识别返回可排序的文本块，供后续规则与人工校正共同使用。
- OCR 与字段解析解耦：`OCRService` 不产生任何结构化字段。
- 识别失败可恢复，不丢失原图。

**Non-Goals:**

- 不实现版面分析（表格、段落层级）。
- 不做多语言自动检测（固定中英双语）。
- 不追求与 CamCard 逐字符一致。

## Decisions

1. **`recognitionLanguages = ["zh-Hans", "en-US"]`，开启语言纠正**
   - 理由：名片以中英为主；语言纠正能修正少量 OCR 错字。
   - 备选：仅英文（被否：中文名片全部失效）；自动检测（被否：额外延迟且不稳定）。

2. **按 Vision 返回顺序赋 `lineIndex`**
   - 理由：版面坐标在倾斜/竖版时不可靠；顺序保留便于规则与调试。
   - 备选：按 `boundingBox` 从上到下排序（被否：多栏名片会打乱阅读顺序）。

3. **置信度随观察一起保存**
   - 理由：后续可据此提示"低置信字段"，并支撑错误分析。
   - 备选：只存文本（被否：无法定位质量问题）。

4. **OCR 错误不向上抛出，而是返回空数组并在管线层提示**
   - 理由：用户可以重拍或手工录入；抛错会阻断整条链路。
   - 备选：直接抛出（被否：用户体验与恢复路径更差）。

## Risks / Trade-offs

- [Vision 对竖版名片的行序可能不符合阅读方向] → 依赖方向校正先完成；错误案例进入评估报告。
- [高分辨率图像识别耗时较长] → 在后台执行；后续可增加缩放预处理。
- [`recognitionLanguages` 在低版本系统上的支持差异] → 部署目标 iOS 17，风险可接受。

## Migration Plan

无数据迁移。OCR 原始结果当前不落库，仅在本次扫描的内存 `ScanResult` 中保留；是否持久化由 `0006` 决定。
